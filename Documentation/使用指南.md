# SceneScope 使用指南

[项目说明](../PROJECT.zh-CN.md) · [English](User-Guide.en.md)

SceneScope 提供静态场景诊断与运行时性能排查两条工作流。静态诊断把场景问题、Scene 视图定位、可撤销修改和离线报告连接起来；1.1 新增 Runtime 模块，可在 Editor Play Mode 和 Development Build 中采集帧间隔、CPU/GPU 时间、GC 与实际渲染计数。静态检查评分仍不能换算成 FPS 或优化百分比。

运行时排查入口为 **Tools → SceneScope → 运行时性能排查**。完整的 Editor 操作、开发包接入、设备 JSON 回导与指标边界见 [运行时排查指南](运行时排查指南.md)。本页后续的规则、评分、修复和场景 CI 说明均属于静态诊断工作流。

## 安装与打开

- 当前工程已经将工具放在 `Packages/com.scenescope.diagnostics`，作为 embedded UPM package 使用。
- 复制到其他工程时，将整个包目录放到目标工程的 `Packages` 下。包声明最低版本为 Unity 2022.3；实际验证环境见下文，不据此推定所有 Unity 版本均已验证。
- 等待脚本编译完成，静态检查选择 **Tools → SceneScope → 打开诊断面板**；运行时排查选择 **Tools → SceneScope → 运行时性能排查**。
- 场景扫描与两个面板位于 Editor 程序集；1.1 的 `SceneScope.Runtime` 程序集可进入 Player，不依赖 UnityEditor 或第三方包。仅显式添加或创建 `SceneScopeCapture` 才会采集，采集路径只在 Editor 或 Development Build 中启用，正常 Release 构建中的启动入口不采样。

运行时读数提供排查线索，不会自动定位到具体函数、GC 暂停原因或逐 Draw Call 对象。CPU 主线程时间包含等待；GPU 数据异步返回，不保证与同一行 CPU 观测对齐；GC 分配字节数不等于暂停耗时；未支持的指标显示 N/A。最终结论需要结合目标设备 Profiler 与 Frame Debugger 验证。

在本工程目录的 PowerShell 中执行 `./Open-SceneScope.ps1`，也可直接启动 Unity 并打开诊断面板。脚本读取 `ProjectSettings/ProjectVersion.txt`，从 D 盘常用安装目录及 Unity Hub 配置查找对应编辑器；找不到时使用 `./Open-SceneScope.ps1 -UnityPath '你的 Unity.exe 完整路径'` 指定。仅在当前是一个干净的未保存空场景时，启动入口会尝试打开已有演示场景；其他场景状态保留。

## 五分钟演示路线

1. 点击面板中的 **生成演示场景**，或选择 **Tools → SceneScope → 生成演示场景**。按 Unity 的提示处理当前未保存场景。
2. 演示资源生成在 `Assets/SceneScopeDemo/Generated/`；已有目录会使用新后缀，演示场景名为 `SceneScope_Demo.unity`。场景用四个区域呈现高面数、小物体阴影、深层级和物理配置问题，还包含空网格与未激活对象等检查样本。
3. 点击 **扫描已加载场景**。扫描覆盖已加载的普通场景，可使用 **取消扫描** 中止；扫描期间避免修改场景，以保持结果可比较。
4. 通过严重程度、分类和文本筛选查看问题。选中条目后，使用 **定位对象** 或 **在 Scene 中聚焦**；开启 **Scene 热力图**，将问题与实际场景位置对应起来。
5. 点击 **固定为基线**。选中“小物体开启了阴影投射”问题，点击 **预览并修复**，阅读清单与视觉影响后确认。工具关闭对应 Renderer 的 Cast Shadows，支持 Unity Undo。
6. 再次扫描，比较问题数量与评分变化；检查阴影的视觉变化。可以用 Ctrl+Z 撤销，再重新扫描核实恢复。检查项减少不代表已测得运行性能提升。
7. 点击 **HTML** 输出独立离线报告，或点击 **JSON** 输出结构化数据。HTML 可在浏览器直接打开，也可通过浏览器打印为 PDF。

## 如何理解指标

| 指标 | 统计含义 |
| --- | --- |
| GameObject / Renderer | 扫描范围内的组件数量；默认包含未激活对象，Renderer 数也可能包含禁用组件 |
| 网格三角形 | 对每个 Renderer 的网格引用累计，包含全部 LOD；共享网格的多次引用会多次计数，不等于某一帧实际提交量 |
| 材质 / 纹理 | 对共享材质及其引用纹理去重；不会通过 `renderer.material` 创建材质副本 |
| 纹理内存估计 | 对引用纹理调用 Unity 内存 API 后累计，是编辑器中该对象的估计值，不是目标设备实际显存 |
| 实时阴影灯光 | 激活、启用、非 Baked 且开启阴影的灯；Mixed 也纳入保守统计 |
| 投影对象 | 扫描范围内 Cast Shadows 不为 Off 的 Renderer 数量 |
| 评分 | `max(0, 100 - 错误×12 - 警告×3 - 提示)`，仅是规则检查的启发式摘要 |

默认预算为单网格 5,000 三角形、纹理单边 2,048 px、单 Renderer 2 个材质槽、层级深度 8、2 盏实时阴影灯、场景 300 个 Renderer 和 250,000 三角形。小物体阈值为世界包围盒最大边小于 0.6 Unity 单位。预算应按项目、目标硬件及美术规格调整，Unity 单位不强制等于物理米。

## 内置规则

| 编号 | 检查项 | 处理方式 |
| --- | --- | --- |
| SS001 | Missing Script | 错误；人工恢复脚本引用或确认废弃 |
| SS002 | Renderer 缺少网格 | 错误；人工关联网格 |
| SS003 | 单网格三角形超预算 | 警告；检查 LOD 与屏幕占比 |
| SS004 | 材质槽超预算 | 警告；用 Frame Debugger 核实实际提交 |
| SS005 | 空材质槽 | 错误；人工补齐引用 |
| SS006 | 小物体投影 | 提示；支持预览、关闭 Cast Shadows、Undo |
| SS007 | 动态刚体关联非凸 MeshCollider | 错误；人工选择合适碰撞方案 |
| SS008 | 纹理边长超预算 | 警告；检查目标平台 Max Size |
| SS009 | 纹理开启 Read/Write | 警告；确认 CPU 访问需求后调整 |
| SS010 | 场景材质中的 Default 纹理未开 Mip Map | 提示；按贴图用途判断 |
| SS011 | 实时阴影灯超预算 | 警告；评估烘焙与阴影策略 |
| SS012 | Renderer 数量超预算 | 警告；检查可见性、LOD 和合批 |
| SS013 | 场景引用几何量超预算 | 警告；结合实际视角分析 |
| SS014 | 多个启用的 AudioListener | 错误；检查相机切换逻辑 |
| SS015 | 层级深度超预算 | 提示；每条分支在首次超过阈值处报告 |
| SS016 | MeshCollider 缺少网格 | 警告；人工检查碰撞引用 |

## 修改与报告

扫描和报告导出不会修改场景。修复只针对可解析、仍存在于已加载普通场景中的投影 Renderer，跳过资产对象、Preview Scene、已关闭投影和 Shadows Only。修复会改变画面，并将场景标记为未保存；是否保存由使用者决定。

HTML 包含扫描时间、场景路径、阈值、指标、问题证据及建议，不依赖网络资源或脚本，所有场景及资源文本均进行 HTML 转义。JSON 使用 Unity `JsonUtility` 输出可序列化字段：枚举为整数，运行时对象引用不写入；`Score` 是计算属性，不是 JSON 字段，可依据严重程度数量重算。GlobalObjectId 与资源路径用于记录定位信息，是否仍可解析取决于原工程资源是否存在。

## CI 与批处理

`SceneScope.Editor.SceneScopeCI.ScanBuildScenes` 是生产场景检查入口，必须在 Unity `-batchmode` 下调用，使用默认规则与阈值。在工程根目录执行以下 PowerShell 示例，并将编辑器路径替换为本机安装位置；先关闭该工程的其他 Unity 实例：

```powershell
$unityPath = 'D:\path\to\Unity\Editor\Unity.exe'
$projectPath = (Get-Location).Path
New-Item -ItemType Directory -Force -Path (Join-Path $projectPath 'artifacts') | Out-Null
& $unityPath `
  -batchmode -nographics `
  -projectPath $projectPath `
  -executeMethod SceneScope.Editor.SceneScopeCI.ScanBuildScenes `
  -sceneScopeReport (Join-Path $projectPath 'artifacts/ci') `
  -sceneScopeFailOnError `
  -logFile (Join-Path $projectPath 'artifacts/ci.log')
```

`-sceneScopeReport` 指定报告目录，省略时使用工作目录下的 `artifacts/ci`。`-sceneScopeFailOnError` 会在发现错误级问题时返回退出码 2；正常完成返回 0，执行异常返回 1。入口会主动退出 Unity，不需要添加 `-quit`，不写回场景。

CI 会逐个单独加载 Build Settings 中启用的场景，为每个场景生成 `000-场景名.json` 与 `000-场景名.html`，编号从 000 递增；`summary.json` 汇总 UTC 时间、场景数量、错误/警告数量和 HTML 报告路径。已启用场景有任一路径缺失就直接报错，避免部分扫描被误认为完整检查。逐场景检查适合互斥关卡；实际以 Additive 同时运行的组合，需要在编辑器加载完整组合后额外扫描。

## 静态诊断验证状态

工程提供 `SceneScope.Editor.SceneScopeValidation.RunBatch` 批处理验证入口，预期将结果写入工程的 `artifacts/validation.json`，并导出 `demo-report.json`、`demo-report.html`。检查涵盖演示扫描、未激活对象范围、阈值变化、修复与 Undo、报告导出。

2026-10-23 已在本机 Unity 2022.3.62f3 实际执行：34/34 项集成检查通过。演示场景扫描得到 14 条诊断，批量关闭 8 个小物体的投影后剩余 6 条，单次 Undo 恢复原始结果。检查项减少不代表已测得帧率提升。

`SceneScope.Editor.SceneScopeUIValidation.RunBatch` 另行通过了真实 EditorWindow 构造、USS 加载、异步扫描完成回调、ListView、不同范围基线拒绝和过期结果保护检查；该入口需要图形设备，不加 `-nographics`。这是程序化检查，不是原生界面截图验收。

CI 实测扫描了保存的演示场景，输出每场景 HTML/JSON 与 summary.json；启用 `-sceneScopeFailOnError` 后，对演示中故意保留的 2 条错误返回预期退出码 2。HTML 报告已在内置浏览器检查实际排版。原生编辑器窗口的视觉交互尚未完成截图验证。

详细证据保存在 `artifacts/validation.json`、`artifacts/ui-validation.txt`、`artifacts/unity-validation.log`、`artifacts/unity-ui-validation.log` 和 `artifacts/ci/summary.json`。这些是本地验证产物，未放入可复用工具包。

以上检查属于原有静态诊断能力，不代表 1.1 新增 Runtime 模块的所有指标或所有目标设备已经通过验证。运行时功能的采样结果必须结合本次实际日志、报告中的设备与指标支持情况核实。
